# 目标

严谨检查并修正项目中题目参考答案的三大类质量问题：
1. **跨领域答案错配** — 答案内容与主题完全无关
2. **空模板答案** — 答案只含元模板指示语，没有任何领域知识
3. **不相关答案重复** — 不同主题共享同一答案文本

# 范围 / 非范围

**范围：**
- `data/concrete-refs/` 下 8 个 JSON 文件（java.json, go.json, python.json, frontend.json, ai.json, security.json, ops.json, qa.json）
- `data/approved-questions.json` 中已有 referenceAnswer 的准确性抽查
- `shared/concreteReferenceCatalog.js` 中的 `INLINE_PATTERN_RULES` 正确性

**非范围：**
- 不修改 `referenceAnswerResolver.js` 的匹配逻辑
- 不新增题目或删减题目
- 不修改 UI 或后端逻辑

# 设计

## 修正原则

1. **每个 key 的 referenceAnswer 必须包含该主题的实质领域知识**，不能只有元模板指示
2. **referenceAnswer 长度目标 150-300 字**（与 java.json/go.json 的既有风格一致），包含：定义、核心机制、关键操作/命令/配置、常见坑和验证方式
3. **excellentAnswer 长度目标 40-80 字**，以"我会"开头，给出第一人称的面试口述版
4. **不跨领域混用** — 每个答案必须严格对应该 key 的主题
5. **内容准确严谨** — 基于业界公认的技术事实，避免过时信息

## 修正格式规范

参照 java.json 的既有高质量答案风格：

```json
"JVM 内存模型": {
  "referenceAnswer": "JVM 运行时数据区：程序计数器、虚拟机栈、本地方法栈、堆、方法区/元空间（JDK8+ 字符串常量在堆）。OOM 排查：Java heap space 用 jmap -histo/MAT 看对象；Metaspace 查类加载泄漏；unable to create native thread 看线程数；Direct buffer 结合 NIO。线程栈区异常用 jstack 看栈帧和局部变量。",
  "excellentAnswer": "我会根据 OOM 信息先判断区域：堆看 dump 和对象分布，元空间查类加载，线程过多看 jstack，直接内存查 NIO 和 MaxDirectMemorySize。"
}
```

# 风险与兼容性

- **风险**：大量文件修改可能引入 JSON 语法错误 → 每个文件修改后立即验证 `JSON.parse`
- **风险**：新写的参考答案可能不够准确 → 遵循业界公认知识，如官方文档、JavaGuide、Go 官方博客等
- **兼容性**：`concreteReferenceCatalog.js` 的 `lookupSkillCatalog()` 按 `category → skill` 查找，key 名称不能变，只能改 value
- **兼容性**：`INLINE_PATTERN_RULES` 中的 pattern 匹配逻辑不受影响，因为只修改 JSON 数据
